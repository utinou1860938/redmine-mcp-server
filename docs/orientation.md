## 1. MCPとは？

---

### MCP登場以前の課題

- AIは「会話」はできるが「行動」ができなかった
- 外部システム（ファイル、DB、APIなど）にアクセスできない
- 毎回コピペで情報を渡す必要があった

---

### MCP = Model Context Protocol

- AIに「手足」を与えるための標準規格
- Anthropic社が2024年に公開
- AIが外部ツールを安全に使えるようにするプロトコル

**たとえ話：**
> MCPは「AIと外部システムをつなぐUSB規格」のようなもの

---

## 2. MCPサーバーとは？

---

### MCPサーバー = AIに渡す「道具箱」

MCPサーバーは、AIが使える「ツール」を提供するプログラム

**ツールの具体例：**
- ファイルの読み書き
- データベースへのクエリ
- 外部APIとの連携（GitHub, Slack, Redmineなど）

---

### 世の中のMCPサーバー例（公式・コミュニティ）

| MCPサーバー | できること |
|------------|-----------|
| Filesystem | ファイル操作 |
| GitHub | リポジトリ・Issue・PR操作 |
| Slack | メッセージ送受信 |
| PostgreSQL | DBクエリ実行 |

※ Redmine用の公式MCPサーバーは存在しない → 今回自作！

---

## 3. MCPクライアントとサーバーの関係

---

### 全体構成図

```
ユーザー
   ↓ 指示
MCPクライアント（Claude Code など）
   ↓ MCP通信
MCPサーバー
   ↓ API通信
外部システム（Redmine, GitHub など）
```

---

### 対応MCPクライアント

- **Claude Code** - CLIツール
- **Claude Desktop** - デスクトップアプリ
- **Cursor** - AIエディタ
- **Windsurf** - AIエディタ
- その他、MCP対応アプリケーション

---

## 4. MCP通信の仕組み

---

### プロトコルとトランスポート

| 用語 | 役割 | 例 |
|-----|------|-----|
| **MCPプロトコル** | 通信の「言語・ルール」 | JSON-RPC形式 |
| **トランスポート** | 通信の「経路」 | stdio, HTTPS/SSE |

---

### トランスポートの種類

**stdio（標準入出力）**
```
Claude Code ──MCP(JSON-RPC)──> stdin/stdout ──> MCPサーバー
```
- 同じマシン内のプロセス間通信
- ネットワークを経由しない

**HTTPS/SSE**
```
Claude Code ──MCP(JSON-RPC)──> HTTPS ──> MCPサーバー
```
- ネットワーク経由の通信
- リモートサーバーに接続

---

## 5. ローカルMCPとリモートMCPの違い

---

### 比較表

| | ローカルMCP | リモートMCP |
|---|---|---|
| 通信方式 | stdio | HTTPS/SSE |
| 動作場所 | 自分のPC | クラウド |
| プロキシ影響 | **なし** | ブロックされやすい |
| セットアップ | 自分で構築 | 設定のみ |
| カスタマイズ | 自由 | 制限あり |

---

### 社内環境ではローカルMCPが有利

**リモートMCPの課題：**
- 社内プロキシでMCPドメインがブロックされるケースが多い
- 外部サービスへの接続制限

**ローカルMCPなら：**
- ネットワーク制限の影響を受けない
- 社内システム（Redmineなど）と直接API通信できる

---

## 6. RedmineMCPサーバーの紹介

---

### RedmineMCPサーバーとは

社内RedmineをAIから操作できるようにするMCPサーバー

```
ユーザー
   ↓
Claude Code（MCPクライアント）
   ↓ stdio（ローカル通信）
RedmineMCPサーバー
   ↓ HTTPS API通信
Redmine（社内）
```

---

### 解決する課題

**Before：**
- チケット確認のたびにブラウザに切り替え
- 情報をコピペでAIに渡す
- 手動でチケット更新

**After：**
- 会話しながらチケットを確認・更新
- 「自分のチケット見せて」で一覧表示
- AIがチケットを直接操作

---

### 利用可能なツール

| ツール | 機能 |
|-------|------|
| `list_issues` | チケット一覧取得 |
| `get_issue` | チケット詳細取得 |
| `create_issue` | チケット作成 |
| `update_issue` | チケット更新 |
| `add_comment` | コメント追加 |
| `search_issues` | キーワード検索 |

---

### セキュリティ機能

- `--project` オプションでアクセス可能なプロジェクトを制限
- 指定プロジェクト以外のチケットにはアクセス不可
- APIキーはmacOS Keychainで安全に管理

## 8. デモ / 使用例

---

### 使用例①：チケット一覧の取得

**ユーザー：**
> 自分に割り当てられたチケットを見せて

**AI（Claude Code）：**
> RedmineMCPサーバーの `list_issues` ツールを使用します...
> 
> 以下のチケットが割り当てられています：
> - #123: ログイン機能の実装
> - #124: バグ修正：画面遷移エラー

---

### 使用例②：チケットの更新

**ユーザー：**
> チケット#123の進捗を50%にして

**AI（Claude Code）：**
> `update_issue` ツールで更新しました。
> チケット#123の進捗率を50%に設定しました。

---

### 導入前後のワークフロー比較

| | Before | After |
|---|---|---|
| チケット確認 | ブラウザで確認 | 会話で確認 |
| 情報共有 | コピペ | 自動取得 |
| チケット更新 | 手動入力 | 会話で指示 |
| コンテキスト切替 | 頻繁 | 不要 |

## 9. Claude Code 活用Tips

---

### 設定ファイルの役割

| ファイル | 役割 | 共有 |
|---------|------|------|
| **CLAUDE.md** | プロジェクトの指示書 | チームで共有（Git管理） |
| **MEMORY.md** | AIの記憶 | 個人用（Git管理外） |
| **.mcp.json** | MCPサーバー設定 | チームで共有（Git管理） |

---

### CLAUDE.md と MEMORY.md の違い

**CLAUDE.md**
- プロジェクトのルールや慣習を記述
- 「このプロジェクトではTypeScriptを使う」など
- リポジトリにコミットしてチーム全員で共有

**MEMORY.md**
- 会話の中でAIが学んだことを蓄積
- 「このユーザーは〇〇を好む」など
- 個人の作業ディレクトリに保存

---

### よく使うスラッシュコマンド

| コマンド | 説明 |
|---------|------|
| `/help` | ヘルプを表示 |
| `/clear` | 会話履歴をクリア |
| `/mcp` | MCP接続状況を確認 |
| `/loop` | 定期実行（例: `/loop 5m /mcp`） |

---

### /mcp コマンド

MCPサーバーの接続状態を確認できる

```
> /mcp

Connected MCP servers:
  - redmine (5 tools)
    ├─ list_issues
    ├─ get_issue
    ├─ create_issue
    ...
```

MCPサーバーが認識されていない場合はここで確認
